How each target is handled
  1. Baseline CTS run on the OEM build
  2. Root cause: device probes + local LLM reading the OEM source
  3. {% if builds %}Patch the OEM source (smallest change){% else %}Apply one allow-listed remediation{% endif %}
  4. {% if builds %}Build the image & flash the DUT{% else %}Re-run the same tests{% endif %}
  5. Re-run CTS; revert the change if it did not help, try again
  6. Green twice → patch handed over for review

Every step above is a real TradeFed invocation on the listed DUT; pass/fail counts come from its test_result.xml. Device-side changes come only from config/remediations.yaml. "Root cause proven" means a device-side workaround made the tests pass; the permanent fix must ship in the build.
